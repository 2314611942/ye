## 性能对比

以下为上一轮地图优化的对照记录。同一台 Linux / Chrome、1440 × 900、Vite 开发服务器、正常动效，Chrome DevTools Protocol 将 CPU 限速为4倍。持续模拟120帧指针拖动，去掉首帧后记录119个帧间隔。数据为本机单次前后对照，不代表所有设备的帧率。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 帧间隔中位数 | 68.1 ms | 16.6 ms |
| 帧间隔 P95 | 75.6 ms | 18.5 ms |
| 超过33.4 ms的帧数 | 91 / 119 | 0 / 119 |
| 拖动过程脚本执行时间 | 6169 ms | 111 ms |

[原始测量数据](performance-results.json)；复测命令 `node scripts/performance-check.mjs sample`，默认连接5173端口，可通过 `PERFORMANCE_URL`、`CHROME_PATH` 修改。请避免与其他浏览器测试同时运行。另有浏览器断言确认拖动期间静态地形节点没有属性修改或替换。

上一轮箭头避让更新后另测生产预览（4173端口），保持1440 × 900、4倍 CPU 限速及相同拖动方法：帧间隔中位数16.6 ms，P95为17.5 ms，119帧中没有超过33.4 ms的帧，脚本执行时间64.5 ms。原始记录见 [箭头更新后测量](performance-arrows.json)。此记录使用生产构建，不与上表开发服务器结果作为严格前后对照，亦早于本轮缩放稳定性修复。

本轮修复固定了路线形状及编号相对地图的位置。路线仅在节点布局变化时规划，缩放时等比换算同一条路线并保持箭头与圆点之间的间距；取消了缩放停止后的重新选路。100种路线布局组合均验证复用同一份规划，不再为每个缩放比例独立规划后测试。
